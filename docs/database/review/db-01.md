## Role matrix

All groups are NOLOGIN, NOSUPERUSER, NOCREATEDB, NOCREATEROLE and NOBYPASSRLS.
The migration login receives owner membership; runtime logins never receive it.

| Group                    | Current DB-01 permissions                                                                                         | Explicit denials                                                                          |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `library_owner`          | Owns schemas, migration history, marker, all domain/audit tables and routines                                     | No privileged role attributes; never a runtime credential                                 |
| `library_importer`       | Named domain/audit SELECT/INSERT/UPDATE, required sequence USAGE/SELECT, relation-link DELETE, value-hash EXECUTE | No owner membership, DDL, TRUNCATE, parent/evidence hard deletion or owner-request access |
| `library_editor`         | Schema USAGE and EXECUTE on create/patch book, patch feedback, patch assessment and archive                       | No direct DML/read on base/audit tables, helper execution, DDL or owner membership        |
| `library_private_reader` | Named domain/audit SELECT and value-hash EXECUTE                                                                  | No mutation, owner-request reads, DDL or owner membership                                 |
| `library_public_reader`  | `api_public` USAGE only; no public views are delivered                                                            | No base/audit/provenance access, owner operations, DDL/TEMP or owner membership           |
| `library_ranking_worker` | Reserved group and synthetic login; no current grants                                                             | No private reads/writes, owner membership or DDL/TEMP                                     |

PUBLIC schema access, database CREATE/TEMPORARY and new owner routine execution are revoked.
Future objects do not automatically become public. Runtime permission tests use actual logins.
The migration owner can manage its own SQL objects; SQL privileges do not replace a future owner
authentication design. There are no private HTTP features, RLS claims, public catalogue views,
imports, enrichment tables or ranking/event behavior in DB-01.

## Required reviewer checks

- Confirm that empty-target purpose/instance identity cannot be confused with a diagnostic URL;
  target validation rejects remote/pooler hosts, connection overrides, wrong names and inherited `DATABASE_URL`.
- Inspect bootstrap role membership and actual creating-role default privileges. Verify the owner is
  the NOLOGIN group rather than a runtime login; no real passwords occur in SQL.
- Recompute checksums against the catalog and confirm status is read-only. Review lock release,
  one-file transactions and the connection-loss/partial-failure boundaries.
- Review NULL branches, calendar-month/year bounds and unconstrained numeric scale checks; confirm
  finite values, immutable stable IDs, author-existence at COMMIT and all FK/index relationships.
- Review fixed patch keys and numeric/genre-set request normalization. Stable IDs, actor and versions
  cannot be claimed through JSON. New native IDs are generated by PostgreSQL.
- Verify shared gate → request lock → parent → children ordering, idempotent retry, expected-version
  failure and independent feedback/assessment versions. There is no retry with a new request identity.
- Inspect all six definer routines, including the deferred author trigger, for schema qualification,
  `pg_catalog, pg_temp` search paths, owner ownership and denied direct PUBLIC/helper execution.
- Verify content replacement resets assessment review. SQL hashes use `pg-jsonb-text-v1`, exact
  decimal/bigint strings and the same DB helper for verification; no JS/SQL byte-equivalence assumption.
- Check server-only Nx edges and built-browser scans; the scan complements lint and does not claim
  to be a general secret detector. No migrations run during build or API startup.

## Evidence and unresolved gates

The final suite passed **79/79 on PostgreSQL 16.15 and 79/79 on 18.6** locally. No tests skipped.
It includes checksum drift, invalid SQL rollback, concurrent runners, induced backend loss,
missing/wrong markers, unsafe inherited groups, actual default privileges, temporary-object denial,
concurrent expected versions, independent child versions, malformed payloads/URLs and uncertain dates.
Application quality checks, 10 browser/HTTP tests, 20 context tests and two bundle scanner tests passed.
See the handoff for exact commands, digests and Golden Path verification.

Independent SQL/permissions review and Golden Path ADR acceptance are not performed. CI is configured,
but no remote CI run is claimed. Hosted target approval/manifest and actual hosted-major rehearsal,
backup/restore, real-data import and production bootstrap remain later gates.
